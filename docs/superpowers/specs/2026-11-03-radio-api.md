# Radio: the contract between the server and the page

Shared by the two halves of the work (backend/, frontend/). Product decisions:
`2026-11-03-radio-design.md`; the look: `2026-11-03-radio/prototype.html`, variant **C · Cloud**.
Everything below is the server's JSON; ids are Navidrome song ids unless said.

## Types

```ts
type Tempo = 'slow' | 'mid' | 'fast';
const MOODS = ['driving','energetic','aggressive','intense','anthemic','epic','upbeat','joyful','playful',
  'uplifting','hopeful','groovy','gentle','calm','dreamy','romantic','tender','intimate','melancholic',
  'nostalgic','dark','tense','dramatic','reflective','atmospheric','cinematic'] as const;
const STYLES = ['rock','alternative','hard-rock','progressive','pop','singer-songwriter','folk','chanson',
  'soul','r&b','blues','jazz','funk','latin','hip-hop','electronic','dance','soundtrack','world','classical'] as const;

/** Where the songs are drawn from: the union of what is on; all off = everything that plays. */
interface RadioPool {
  stars: number | null;      // albums at this many stars and more (3, 3.5, 4, 4.5, 5), null = off
  hearts: boolean;           // the songs hearted in Navidrome
  popular: boolean;          // the albums' popular tracks (track_popularity, popularTracks)
  genre: 'both' | 'classical' | 'other';   // classical as the shelves tell it (Album.search's classical:)
  wholeWorks: boolean;       // a work's movement drawn brings the whole work
}

/** What a prompt is heard as; every field optional, an empty list = no constraint. */
interface RadioCriteria {
  energyMin?: number | null; energyMax?: number | null;
  tempos?: Tempo[]; moods?: string[]; styles?: string[]; langs?: string[];
}

interface RadioSong {
  songId: string; title: string; artist: string;
  albumId: number; album: string; cover: string | null;   // cover: DexVault image path, as elsewhere
  discNumber: number; track: number; durationSec: number | null;
  work: string | null; movement: string | null;
  energy: number; tempo: Tempo; moods: string[]; styles: string[]; lang: string;
}
```

## Endpoints

- `POST /api/radio/criteria` `{ prompt }` → `RadioCriteria`. The local LLM (one request at a time,
  in turn with the guides), moods and styles kept to the closed lists. 400 for no prompt.
- `POST /api/radio/next` `{ criteria, pool, count, ahead: string[], keep?: string[] }` →
  `{ songs: RadioSong[], poolSize: number, fitting: number, missingFiches: number }`.
  `count` 1–50; `ahead` the songs already queued (never drawn again, and the artist rules count
  them); `keep` the band as the page shows it: those still in the pool that still fit (not ruled
  out, one of the moods asked when there are; the tempo only ranks) come first, in their order, and only
  the rest of `count` is drawn, the LLM not asked when nothing is missing. ↻ sends no `keep`. Draws candidates from the fiches of the pool that fit the criteria, about 40, at most 3 per
  artist, then lets the LLM choose `count` of them (seeing the last 20 that left); falls back to
  the best fits when the LLM fails. Then, in code: at most 2 per artist among ahead + new, never two
  in a row by one artist; a work's movements together and in their order (whole with
  `wholeWorks`). Leaves out songs that left lately (below). `songs` may be shorter than `count`,
  empty when nothing fits: the page says so.
- `POST /api/radio/left` `{ songId, how: 'played' | 'skipped' }` → `{ ok: true }`. Kept in
  `radio_history`; a song comes back after half of the pool (counted in songs left since) or 30
  days, whichever first; a skipped one twice as late.
- `GET /api/radio/fiches` → `{ songs: number, withFiche: number, queued: number, writing: boolean }`.
- `POST /api/radio/fiches` `{ pool }` → same shape: puts the pool's songs with no fiche first in the
  writer's queue.

## Fiches

- Table `track_fiches`: `recording_key TEXT PRIMARY KEY` (the track's MusicBrainz recording id, else
  `album:<albumId>:<disc>:<no>`), `energy INTEGER`, `tempo TEXT`, `moods TEXT` (JSON),
  `styles TEXT` (JSON), `lang TEXT`, `model TEXT`, `made_at TEXT`. One recording, one fiche: the
  same song on two albums shares it.
- Written by the local LLM (coverScanService's getConfig), 25 songs a request, in the same
  one-at-a-time queue as the album guides; at night by itself (with the guides' auto-writer), the
  pools asked for first, an album added or ripped queued. Words off the lists are dropped.
- Classical: a song is classical when its album is (as the shelves tell it), never by the album's
  tags alone.

## The page

- `frontend/src/services/radioService.ts` wraps the endpoints.
- The Listen Next banner gets `Listen Next | ✦ Radio` (Segmented, kept in the browser). Radio's
  banner, variant Cloud: the prompt (editable, ↵), recent prompts (kept in the browser, 6), the pool
  in chips (a menu where sources add up, stars 3–5 by halves, the count of songs), genre, whole
  works, "Heard as" chips each removable, 10 covers ahead with mood and style tags, an energy
  gauge and ✕, ▶/⏸, ↻, Save as mixtape… (name, 10/20/30/45, 30 by default, `createMixtape`), the
  band's tint following the mean energy, an empty state offering everything that plays.
- Playing: DexVault's player plays the radio as an album "Radio · <prompt>" of its songs; it is
  refilled to 10 ahead as it goes (the player can append tracks), each song leaving reported to
  `/api/radio/left` (played when half heard or more, skipped else). Listen Next is left alone.
